# Conference Deadlines

A static web page that lists research meetings with their submission deadlines, so that a call for abstracts that closes months before a meeting is not missed. Views: a deadline table with day countdowns (default), a list, a month calendar, and a map with numbered points and straight line distances from a home ZIP code. Every meeting and deadline has the same three actions: Track (a personal list on the page), Download (a calendar file, Google Calendar or Outlook on the web) and Hide. Filters, tracked and hidden meetings, added meetings, ZIP code and reminder settings stay in the browser and can be encoded into a share link; there are no accounts and nothing is transmitted.

## Fields

One site serves every field. A field profile is a saved filter with its own address: `/psychiatry/` and `/neurology/` open the page limited to that field (plus the campus events), with the field's subtitle, its own calendar feed and its own tracking list in the browser. The masthead shows links between All fields and each profile, so a visitor can widen the view at any time. Profiles are defined in `data/site.json`; adding one is a data change and a rebuild.

## Files

| Path | Purpose |
|---|---|
| `index.html` | The whole application: markup, styles, code, an embedded snapshot of the database and the geographic tables. Works from a web server or opened directly as a file. |
| `data/site.json` | Site title, subtitle and the field profiles. Edited by hand. |
| `data/meetings/*.json` | The database, one file per meeting series (all editions of one meeting in one file, named after the id without its year). Edited by hand or through the merge script. |
| `data/schema.md` | Field reference for a meeting record. |
| `data/events.json` | Generated: the served database, assembled from the files above. |
| `data/events.csv`, `data/deadlines.csv` | Generated flat exports. |
| `data/geo.json`, `data/zip5.json` | Map outlines (Natural Earth 1:110m, public domain) and ZIP code centroids (GeoNames, CC BY 4.0). |
| `calendar.ics`, `calendar-<field>.ics` | Generated subscription feeds with reminders 30, 7 and 1 days before each deadline. |
| `ics/<id>.ics` | Generated per meeting calendar files. |
| `<field>/index.html`, `manifest-<field>.webmanifest` | Generated: the redirect stub and home screen manifest for each field profile. |
| `manifest.webmanifest`, `icons/` | Home screen installation on iOS and Android. |
| `scripts/build.py` | Validates the data, assembles the database, embeds the snapshot, writes every generated file. Python 3, standard library only. |
| `scripts/merge_research.py` | Places research records into the right series files. |
| `scripts/check_sources.py` | Re-fetches every recorded source page and flags records whose pages failed, changed, or no longer show the recorded dates. |
| `scripts/make_subset.py` | Creates a standalone copy of the site with a filtered database, for hosting a single field elsewhere. |
| `.cpanel.yml` | Deployment recipe for cPanel Git Version Control; the copy list is regenerated by the build. |

## Updating the data

1. Add or edit records in `data/meetings/`, or merge a JSON file of records with `python3 scripts/merge_research.py file.json`. A new meeting series gets a new file automatically.
2. Run `python3 scripts/build.py` from the project root. The build writes nothing if the data has errors (duplicate ids, missing areas, bad dates) and prints warnings for missing dates, unknown tags or dashes in text.
3. Commit and deploy (see Hosting).

`python3 scripts/build.py --check` validates without writing. `python3 scripts/check_sources.py` lists records whose source pages should be re-checked.

Ids never change once published: share links, calendar subscriptions and the per meeting files all refer to them. A new edition of a meeting gets a new id with its year, in the same series file.

The page loads `data/events.json` from the server on each visit and falls back to the snapshot embedded in `index.html` when the file is unreachable (for example when opened from disk). The About dialog reports which copy is in use and its date.

## Hosting

The site is static. Upload the generated files to any web server, or publish the repository with GitHub Pages (Settings, Pages, deploy from the `main` branch, root folder). On cPanel, clone the repository with Git Version Control and deploy; `.cpanel.yml` copies the site into `public_html`. No server side code, database or special configuration is needed. Relative paths work from a subdirectory.

## Local preview

```bash
python3 -m http.server 8455 --directory .
```

Then open `http://localhost:8455/`, `http://localhost:8455/psychiatry/` or `http://localhost:8455/neurology/`.

## Installing on a phone

iOS Safari: Share, Add to Home Screen. Android Chrome: Install app from the menu. A field view installs under the field's name and reopens filtered. On iOS the Download action for a meeting opens the static `ics/<id>.ics` file, which Safari hands to the Calendar app; per deadline reminders and exports are generated in the browser and may not download from the installed home screen copy, so use Safari itself for those.

## Reminders

Reminders live in the calendar files, not in the page. The Download action opens a chooser: the .ics file carries one alarm per selected lead time (chips under Reminders in the side panel), firing at 9:00 in the morning that many days before the deadline. The Google Calendar and Outlook links create a single event without alarms because those services set reminders on their side. The subscription feeds use 30, 7 and 1 days.

## Tracking list: no accounts

There is no login. The Tracking list, hidden meetings, added meetings, filters and settings are stored only in the browser that made them. They are not saved anywhere else, and a different browser, device or private window starts empty. To keep a list or move it to another device, use Share and export: the share link contains the whole list as text in the address, so bookmarking it, sending it to yourself, or saving it in a note preserves the list, and opening it restores everything. The calendar feed and the downloaded calendar files are the other durable copy: once a deadline is in a calendar app it no longer depends on this page.

## Personal list, filters and distance

The Tracking list ignores the topic, area, region and distance filters unless "Apply topic, region and distance filters to this list" is ticked above it; search and the past meetings toggle always apply. Hiding a meeting also removes it from the tracking list. The home ZIP code can be typed on the map or under Distance in the side panel (the same setting); Distance also offers a "within N miles of home" filter. Reset opens a dialog with separate choices so nothing is cleared by a single click.

## Areas of interest

Each meeting carries an `areas` list. On the all fields view an "Areas of interest" chip group appears above Topics, the topic list narrows to the selected areas, and the detail panel lists a meeting's areas. Meetings that belong to two fields appear under both without duplication. Field views hide the chip group because the field already fixes the areas.

## Data sources

Meeting dates and deadlines come from organizer websites; each record lists its source pages and an access date, and the Data sources panel lists every organizer. Deadlines marked with an asterisk follow the prior edition's timing and should be confirmed on the organizer page.

Geographic data: Natural Earth 1:110m cultural vectors (public domain) for the map outlines, and GeoNames postal code data (Creative Commons Attribution 4.0) for ZIP code centroids. Distances are great circle distances, not driving distances.
